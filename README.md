# 课程助手

上传老师讲的课程资料，按距离考试的时间倒排一份能执行的复习计划。

**核心不是"AI 总结资料"，是"时间约束下的学习决策"**：同一份讲义，
30 天和 3 天给出的方案不是详略差别，而是完全不同的取舍。

---

## 一、怎么跑

```bash
cd D:/career_plan/course-assistant
python -m uvicorn app:app --port 8000
```

打开 http://127.0.0.1:8000

Windows 下也可以直接双击 `run.bat`。


> 注意：这台机器的 pip 默认指向清华源，但那个源取不到包，所以要显式加 `--index-url`。

## 一·五、多份资料怎么合到一起

一次最多 10 份，可以分几次拖进来，会在列表里累加；点「移除」删单个，点「全部清空」重来。
支持混格式（比如 3 个 PPT + 1 个 PDF + 1 份 Markdown 笔记）。

合并分两层：**先把文件拼起来（不出错），再把概念并起来（不重复）**。
这两件事难度差一个量级，分开说。

### 第一层：拼接（`core/extract.py`）

三条约定，改这块代码时别破坏：

- **chunk id 全局连续**，不按文件各自从 1 开始——否则知识点引用的 id 会串到另一份文件
- **每个 chunk 记住来源文件**，`source` 变成「数据结构讲义 · 第 3 页」，否则多份资料里「第 3 页」有歧义
- **单个文件解析失败不拖垮整批**，记进 `meta.skipped` 继续走；全部失败才报错

### 第二层：融合（`core/merge.py`）

拼接只保证不冲突，解决不了一个真问题——**同一个概念在不同资料里叫法不同**：

```
教材写「快速傅里叶变换（FFT）」，课件写「FFT」，习题册写「傅立叶变换」
```

抽出来就是三个知识点，排期表里排三遍。用户不会觉得"这个工具真细致"，
只会觉得它在凑数。所以要做同义归并，分两级：

| 级别 | 做法 | 能合什么 | 合不了什么 |
|---|---|---|---|
| 规则 | 归一化后比对（去标点、去括号、去助词、异体字） | 「二叉树的遍历 / 二叉树遍历」「FFT / 快速傅里叶变换（FFT）」 | 「FFT / 快速傅里叶变换」这类中英对照 |
| 模型 | 把所有名字一次性交给模型判断 | 中英缩写、全称、错别字 | 需要模型自己别犯错 |

**但模型在这里不可靠。** 实测它会把这两个判成同义：

```
二叉搜索树的中序遍历  →  二叉树遍历
```

这是上下位关系。合并之后学生的计划里就少一个该学的东西，而且他永远发现不了。
所以模型的结果必须再过一道**字面校验**（`_plausible_alias`），只放行三种：

1. **缩写**：纯英文短串（FFT / TCP / DFT），中英对照没法比字符，整体放行
2. **简称**：一个是另一个的子串，且多出来的部分不是中文
   （「三次握手 ⊂ TCP三次握手」放行；「傅里叶变换 ⊂ 快速傅里叶变换」拦下——多出的"快速"是修饰语，DFT 和 FFT 是两个概念）
3. **异写**：字面重合度 ≥ 0.75（「傅里叶变换 / 傅立叶变换」合；0.71 的「快速傅里叶变换 / 傅里叶变换」不合）

被拦下的合并不丢弃，写进 `merge.rejected`，在页面上能看到——
**工具的判断过程要能被质疑，否则用户没法信任它。**

### 覆盖度：合并顺带拿到的第二个信号

合并之后每个知识点都知道自己出现在哪几份资料里，于是有了 `coverage`：

```
coverage = 这份知识点被几份「不同的资料」讲到
```

（同一份资料里的多个 chunk 只算一次，否则一份 PDF 写得越啰嗦，它的知识点就越显得重要。）

这个东西的价值在于它是**证据，不是预测**：

- `exam_freq` 是模型看讲义猜的
- `exam_hits` 是真题里查到的
- `coverage` 是多份资料交叉验证的

三个老师都讲同一个概念，它就该排前面。所以在 `schedule._value()` 里给
`coverage` 加了 `(coverage - 1) × 0.3` 的加分——上限 0.9，
不会盖过重要性本身，但足以在同分时决定先后。

单份资料时 `coverage` 恒为 1，这一项恒为 0，行为与之前完全一致。

### 已知边界

- 归一化会删掉「的」字。中文里这个字几乎不承载语义，但极少数情况下会误合
- 异体字表是硬编码的，只收确定无疑的几个（傅立叶→傅里叶）
- 合并只在同一个知识点集合内做，跨课程不合并

## 一·六、接真题

第二个上传区是「历年真题（可选）」，可以不传。传了之后做一件事：
**拿真题原文去对知识点，命中就把 `exam_freq` 顶上去，并留下出处。**

为什么值得传：`exam_freq` 打分原来是模型看讲义猜的，它不知道你们老师爱考什么。
真题是唯一能证明「这个知识点真的考过」的东西，所以：

- 命中 1 次 → `exam_freq` 至少 4
- 命中 2 次以上 → 直接 5
- 命中过的知识点，**在冲刺模式下不会被放弃**（`schedule._select` 里优先排序）

实现分两条路，输出结构一致：

| 条件 | 做法 | 精度 |
|---|---|---|
| 配了模型 | 模型读题干，判断每个知识点是否真被考到 | 高，能给出「第 3 题：…」这种证据 |
| 没配模型 | 知识点名称与真题原文做字符匹配 | 粗，但零成本、完全可解释 |

`core/exam.py` 只改三个字段（`exam_freq` / `exam_hits` / `exam_evidence`），
不动知识点本身，所以排期那部分一行代码都没改——它本来就在用 `exam_freq`。

两个已知的边界：

- **模型模式有随机性**：同一份真题跑两次，命中的知识点可能差一两个（边界模糊的那种）。
  这是 LLM 判定的常态，不是 bug。
- **真题解析失败不会让整次分析失败**：会退化成「没有真题」，讲义的分析结果仍然完整。

## 一·七、配套视频

每个要精学的知识点下面会挂 1~2 条 B 站视频，带时长、UP 主、播放量，点开即看。

**为什么不让用户自己搜**：第一版的做法是给关键词——"建议按『数据结构 二叉树遍历 例题』检索"。
那不是建议，是把活推回给用户。他打开 B 站，看到 20 条标题，还是不知道点哪个，
跟自己做没有任何区别，工具等于没做。

所以这里真的去搜，并且替他做一件事：**从 20 条里挑出能看的那一条**。

### 三个难点（按难度排，接口不在其中）

**1. 搜什么词**

课程名放在前面能区分同名内容（「信号与系统 傅里叶变换」比光搜「傅里叶变换」准得多），
但全角括号要拆开——中文平台对「快速傅里叶变换(FFT)」的召回很差，
拆成「快速傅里叶变换 FFT」才搜得出来。

课程名也有反作用：一门课叫「数据结构」，但 FFT 的内容其实属数字信号处理。
所以**带课程名搜不到时会去掉课程名再搜一次**（`_assign` 之后的补搜逻辑）。
「蝶形运算」就是这么找回来的。

**2. 怎么从 20 条里挑（真正的难点）**

这一步踩了三个坑，每个都写进了测试：

| 坑 | 现象 | 处理 |
|---|---|---|
| 泛词误召回 | 搜「快速傅里叶变换」推出「快速排序」，因为都有「快速」 | 相关性做成**硬门槛**，过不了直接丢，不参与排序 |
| 截断造词 | 「FFT复杂度分析」的后 4 字是「杂度分析」，命中了「句法复杂度分析器」 | 名字里带英文缩写时，**缩写必须出现在标题里**，这是唯一可靠的跨领域区分信号 |
| 播放量崇拜 | 「三分钟秒解二叉树遍历」71 万播放，压过 24 分钟的正式讲解 | 打分里时长权重最大：<3 分钟重罚、8~45 分钟加分、>90 分钟（合集）扣分 |

排序只看三件事：**时长是否像一节课**、**标题命中几个核心词**、**播放量的 log**。
外加一条：标题含「速成 / 秒解 / 不挂科」这类词降权——那是应试口诀，不是讲解。

**3. 它随时会挂**

B 站没有公开搜索 API。这里用的是网页端接口，得先访问首页拿 `buvid3` cookie，
否则返回 -412。它不是契约，可能明天就加签名、加验证。

所以做了三层保险：结果缓存 7 天（同一知识点不重复请求）、并发压到 3、
整段检索 25 秒硬超时。**失败一律降级为「这次没有视频」，绝不影响已经算好的计划。**

### 边界

- 只给「精学 / 标准」的知识点搜。速览的内容不配视频——
  为一个 5 分钟翻过去的点看 20 分钟视频，是负收益
- 最多搜 8 个知识点，多了会触发风控
- 宁可不给：相关性过不了的，一条都不推。页面上会说「另外 1 个没找到足够相关的，宁可不给」
- 视频可能被 UP 主删稿，链接失效无法预检

## 二、配模型（可选）

**不配也能用。** 不配时走规则模式：从标题结构和关键词抽取知识点，
说明用模板生成。流程完整、结果可用，只是知识点粒度较粗、说明不够具体。

配了模型之后：知识点按语义抽取、依赖关系更准、每天的学习说明是真正针对内容的。

**方式一：在网页上填**（推荐，改完立刻生效）

页面底部生成按钮右边有个提示链接，点「点这里填 key」展开配置面板：

1. 选服务商（会自动填好地址和模型名）
2. 粘贴 API Key
3. 点**测试连接** —— 会真发一次请求，通不通立刻知道
4. 通了再点**保存**

保存后立即生效，不用重启服务。

**方式二：改 config.json**

复制 `config.example.json` 为 `config.json`，填三个字段：

```json
{
  "base_url": "https://api.deepseek.com/v1",
  "api_key": "sk-xxxx",
  "model": "deepseek-chat"
}
```

任何 OpenAI 兼容接口都行：

| 厂商 | base_url | model 示例 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| 智谱 | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash`（有免费额度） |

**方式三：环境变量**

`LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL`

## 三、它怎么工作的

六个阶段，第二、三、五阶段调模型，第六阶段调网络，第四阶段纯算法：

```
资料 + 课程名 + 考试日期 + 每天分钟数
  ↓
1. 文档解析      PDF/PPTX/TXT → 带章节路径的文本块     【工具】
2. 知识点抽取     文本块 → 知识点 + 三维打分 + 依赖关系   【模型】
3. 三维打分       重要度 / 难度 / 考频                  【模型】
4. 时间倒排       日期 → 知识点列表                     【纯算法】
5. 内容生成       每天的怎么学 / 易错点 / 资源建议        【模型】
6. 配套视频       核心知识点 → B 站上真讲这个的视频       【网络】
  ↓
逐日复习计划表
```

**第 4 步是整个产品的核心，且完全不调模型。**

不给模型排期的理由：让它"帮我排一个 7 天计划"，它会给你一份看起来合理
但无法解释的日程。改成代码算，就变成可复现、可解释——每个知识点为什么
排在第几天，都能说清。

### 排期在做什么

```
容量 = 剩余天数 × 每天分钟 × (1 - 20% 复习预留)
需求 = Σ 每个知识点的预计分钟

负荷比 = 需求 / 容量
  ≥ 1.0  → full    完整覆盖，按章节顺序系统学
  ≥ 0.65 → trim    按权重取舍，次要章节压缩
  ≥ 0.35 → core    只保核心与高频
  < 0.35 → sprint  只保必考，其余全放弃
```

选内容时保证**依赖闭包**：如果留下 B 而 B 依赖 A，A 一定被拉回来（标为"速览（前置）"）。
排顺序用**拓扑排序**：前置永远先于后置。

时间充裕时同层按**章节顺序**排（跟着老师讲课的节奏），
时间紧张时才按**性价比**打乱（先啃高频）。

### 间隔重复

内容 8 天就能学完但还有 30 天时，不会把 8 天连起来学完再空 22 天，
而是把学习日**均匀铺开**，中间夹复习日。这比"一口气学完再复习"记得牢。

## 四、代码结构

```
course-assistant/
├── app.py               FastAPI 路由 + 五阶段流水线编排
├── config.json          模型配置（可选，自己建）
├── core/
│   ├── llm.py           OpenAI 兼容调用 / JSON 重试 / 无 key 降级
│   ├── extract.py       PDF、PPTX、TXT 解析，保留章节路径
│   ├── merge.py         多份资料的同义归并 + 覆盖度  ← 多文件的关键
│   ├── knowledge.py     知识点抽取 + 三维打分 + 依赖建图 + 环检测 + 引用校验
│   ├── exam.py          真题比对，命中则上调考频并留证
│   ├── schedule.py      容量计算 / 权重裁剪 / 拓扑排序 / 分天  ← 核心算法
│   ├── video.py         B 站视频检索 + 相关性过滤 + 质量排序
│   └── generate.py      学习说明、易错点、资源建议
├── tests/
│   ├── test_merge.py    合并逻辑（别名该合、上下位不该合、模型挂了要降级）
│   └── test_video.py    视频推荐（三个坑各有对应用例钉住）
├── web/index.html       单页前端（原生 JS，无构建）
└── data/
    ├── uploads/         上传的原始文件
    ├── video_cache.json 视频检索缓存（7 天）
    └── sessions/        每次分析结果（JSON，可回溯）
```

跑测试：

```bash
python -m unittest discover -s tests -v
```

21 个用例，钉住两件容易改坏的事：**别名该合的合、不该合的不合**，
以及**推荐的视频必须真的在讲那个知识点**。

### 接口

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/` | 前端页面 |
| GET | `/api/config` | 模型是否可用 |
| POST | `/api/config` | 保存模型配置 |
| POST | `/api/config/test` | 用当前填的或临时配置真发一次请求，验证 key 是否可用 |
| POST | `/api/analyze` | 上传并分析。`files` 资料（可重复，≤10 份）、`exam_files` 真题（可重复，≤5 份），立即返回 task_id |
| GET | `/api/task/{id}` | 轮询进度 |
| GET | `/api/result/{id}` | 取结果 |
| POST | `/api/rerun` | 只换考试日期重算（不重跑解析和抽取） |
| GET | `/api/history` | 历史记录 |

`/api/rerun` 是产品里最有用的一个接口：同一份资料，
把日期从 30 天后改成 3 天后，几秒钟就能看到完全不同的方案。

## 五、已知限制

| 限制 | 说明 |
|---|---|
| 扫描版 PDF 不支持 | 需要 OCR。装了 RapidOCR 后可以接上 |
| 知识点粒度取决于资料结构 | 讲义有清晰编号时效果好；纯大段文字会很粗 |
| 规则模式的打分是启发式 | 只能作为兜底，认真用请配模型 |
| 同义合并依赖名字 | 名字完全不同但概念相同的（「快速卷积」和「FFT 求卷积」），两路都合不了 |
| 视频接口不是官方的 | B 站网页端接口，随时可能加签名。挂了就降级为「本次没有视频」 |
| 视频质量靠规则筛 | 相关性靠标题字面匹配，标题写得含糊的好视频可能被漏掉 |
| 没有持久化数据库 | 结果存成 JSON 文件，够本地用 |

## 七、面试时怎么讲这个项目

一句话版本：

> 一个把「课程资料 + 剩余备考时间」转成逐日复习计划的应用。
> 核心是六阶段流水线：文档解析、知识点建图、时间倒排、内容生成、配套视频。
> 其中时间倒排是纯算法实现（拓扑排序 + 权重裁剪），不依赖模型，
> 保证计划可复现、每一条都能解释；每个知识点还挂着真在讲它的 B 站视频。

被追问时能展开的点：

- **为什么不用模型直接排期**：不可复现、不可解释，且随模型升级行为会变
- **怎么防止模型乱给分**：给死的五级标准 + JSON Schema + 解析失败重试
- **依赖成环怎么处理**：建图后做 DFS 环检测，砍掉回边
- **容量不够怎么取舍**：性价比公式（重要度 0.35 + 考频 0.45 - 难度 0.18），
  但保证依赖闭包完整
- **多份资料怎么合**：拼接层保证 id 连续、来源可溯、单文件失败不中断；
  融合层做同义归并，且**不信任模型的判断**——它会把"二叉搜索树的中序遍历"
  并进"二叉树遍历"，所以模型结果要过字面校验（缩写/简称/异写三种放行条件），
  拦下的合并留痕给用户看
- **推荐视频怎么保证不是垃圾**：相关性是硬门槛不是加分项。
  搜「快速傅里叶变换」B 站会返回「快速排序」，「FFT复杂度分析」会返回
  「句法复杂度分析器」——两个坑分别用「核心词分开处理」和「缩写必须命中」解决；
  过了门槛之后才比时长和播放量
- **怎么保证不丢内容**：最后一道兜底，剩余知识点压缩塞进最后一个学习日

这个项目里真正值得讲的不是"用了大模型"，而是**哪几处故意不让大模型做决定**：
排期不让它做（要可复现）、同义合并让它提议但不让它拍板（要可审计）、
选视频完全不给它做（要可验证的硬规则）。
能用代码算的都用代码算，模型只负责它确实擅长的语义理解。
